# 安康守护健康安全网站

基于 Inx-Health 的“记录、目标、分析”产品思路独立设计，包含健康总览、个人档案、日常锻炼、饮食健康、睡眠监测、视力检测和安全健康分析。

游客模式始终显示空记录，不读取旧游客缓存，也不保存游客数据。记录表单不预填数值，游客点击保存时弹出“请先登录账号”，可前往登录页面。旧浏览器缓存保留但不使用。登录后读取当前账号的独立档案；新账号首次进入为空记录。当前本机 MySQL 模式下，账号、健康记录和问诊对话保存在 MySQL；未配置 MySQL 时才使用旧 JSON 数据目录。退出后显示空白游客页面。刷新、重新登录或重启服务不会删除已保存记录；重启服务后需重新登录。

运动和饮食按日期保存，总览统计当天记录；睡眠展示最近 7 次，同一天再次填写会更新该天记录。分析仅作生活习惯参考，不提供医疗诊断。登录页面复用相邻“账号”目录的页面；当前 MySQL 模式下账号数据从数据库读取，旧 JSON 模式才读取相邻目录的 users.json。

“健康看板 → 个人档案”支持填写姓名或称呼、性别、出生日期、血型、身高体重、活动水平、健康目标、过敏或忌口、健康备忘和紧急联系人。档案与当前登录账号绑定，可随时修改或清空；清空档案不会删除运动、饮食、睡眠和视力记录。BMI 由填写的身高体重计算，仅用于日常参考。

视力检测参考 [AI-EYE](https://github.com/MikeDean2367/AI-EYE) 的视力、散光、色觉与历史记录模块，针对网页环境实现为：实体直尺校准后的 E 字左右眼自测、主观散光线条观察、六次颜色辨别练习和护眼建议。摄像头测距与手势识别依赖原项目的 Android 原生组件，本网页未启用。网页结果受屏幕、距离、光线和操作影响，仅作日常参考，不能用于配镜、判断近视度数或替代眼科检查。视力记录独立展示，不计入运动、饮食和睡眠三项安全状态评分。

登录后可在运动、饮食、睡眠和视力记录右侧删除填错的内容。删除前会二次确认，确认后同步更新当前账号档案；游客没有可删除的数据。

本机启动：在 PowerShell 中执行 powershell -NoProfile -ExecutionPolicy Bypass -File 'D:\测试\安全\scripts\start-local.ps1'，它会先启动本机 MySQL，再启动网站。然后访问 http://localhost:3000。按 Ctrl+C 停止网站；MySQL 进程会继续运行，下次启动脚本会复用它。若手动执行 npm start，须确保 MySQL 已先启动。

需要 Node.js 18 或更高版本。首次运行请在本目录执行 npm install；MySQL 模式使用 mysql2 驱动。

## MySQL 数据库模式

本机已安装 MySQL 8.4，数据目录为 D:\测试\mysql-local\data，D:\ankang-mysql 是指向该目录的英文路径入口，仅用于绕开 MySQL 对中文路径的兼容问题。账号、健康记录和问诊对话已从原 JSON 导入 MySQL；原 JSON 保留作备份。网站优先使用环境变量中的 MySQL 配置，否则读取项目外的 D:\测试\mysql-local\app-config.json；只有两者都不存在时才使用旧 JSON。数据库密码不在网页源码中，也不应提交到仓库。启动时会检查或创建 users、health_records、consult_threads 三张表。

PowerShell 示例（将尖括号内容替换成自己的配置，不要把密码发到聊天里）：

    $env:MYSQL_HOST = '<数据库地址>'
    $env:MYSQL_PORT = '3306'
    $env:MYSQL_USER = '<数据库用户名>'
    $env:MYSQL_PASSWORD = '<数据库密码>'
    $env:MYSQL_DATABASE = '<数据库名>'
    $env:MYSQL_SSL = '1'

本机 MySQL 只监听 127.0.0.1，不开放数据库公网端口；云数据库应按服务商要求开启 TLS。上面的环境变量会覆盖本机配置，供以后部署时使用。迁移脚本 node scripts/migrate-mysql.cjs --apply 只导入数据库中不存在的账号和档案，不覆盖已有数据库数据，也不删除原始 JSON；若同名账号与不同 ID 冲突，会报错并停止。正式迁移到服务器数据库前，先备份 MySQL，再在网站停止写入期间迁移，并核对登录、个人记录和管理员统计。

MySQL 与公网部署是两件事：目前服务仍只监听本机 127.0.0.1:3000。正式让其他人访问时，还需部署 Node.js 服务、配置域名/HTTPS、数据库访问控制、备份及稳定的 SESSION_SECRET。

“日常锻炼 → 锻炼记录”下方可制定每周锻炼计划；“饮食健康 → 饮食记录”下方可制定一日饮食计划。参考 [fitness-agent](https://github.com/wxk7099/fitness-agent) 的计算与模板方案，使用本地规则生成，无需 API 密钥，尚未接入大模型对话。训练依据目标、基础、器械、天数和时长安排七天训练及恢复；饮食使用 Mifflin–St Jeor 公式和活动系数估算消耗，并按目标调整热量、展示营养目标及带分量的食谱。食谱估算合计独立展示，不声称与营养目标完全一致；编辑食材后应同步修改营养数值。支持蛋奶素与六类食材排除，其他忌口仅作为备忘，必须自行核对。适用于一般健康成年人，不用于疾病营养处方。

两类计划均可生成后编辑、保存、重新制定和删除，每类保留一份当前计划。游客不显示已保存计划，保存会提示登录；计划按账号隔离、重启后保留，旧档案自动兼容。计划不算已完成记录，实际运动或用餐后仍在上方打卡。

“生活打卡 → 健康挑战赛”提供 21 天早睡、7 天戒糖和每日饮水挑战。登录用户可参加、按日打卡、修改当天入睡时间或饮水量、撤销误填的当天记录；游客不显示任何账号的挑战记录，保存前提示登录。早睡打卡须在 23:00 前入睡，戒糖指当天不摄入含糖饮料或额外添加糖零食，饮水达到 1500 ml 才计入积分。挑战打卡由本人如实填写，不是自动健康检测；7 天与 21 天徽章要求从开始日起连续达标。排行榜按近 30 天达标打卡天数排序，仅显示本人和其他用户的匿名代号。挑战数据与原有记录一起保存在当前用户账号中。

安全健康管理员使用独立的深蓝色登录入口 `http://localhost:3000/account/?mode=admin&returnTo=%2Fadmin%2F`，登录后进入 `http://localhost:3000/admin/` 后台。后台参考 [IHMS](https://github.com/JX05120LLL/IHMS) 的用户端、管理员端分离思路，展示普通用户注册数、实际有记录人数、锻炼/饮食/睡眠/视力记录量、饮食热量与蛋白质均值、睡眠时长均值及挑战进展。睡眠时长单独统计；用户新填写的 1–5 分主观睡眠质量仅统计有评分的记录，旧记录不计入质量均值。空账号不参与对应均值计算。管理员不通过普通用户数据接口写入或修改个人记录，普通用户不能访问后台汇总接口；后台不展示个人医疗备忘与紧急联系人。管理员与普通用户共用同一服务端，但使用不同登录模式和页面。

睡眠记录现在可选填 1–5 分主观质量。后台的主观睡眠质量均值仅统计实际填写评分的记录，同时显示评分条数；旧记录只有时长时不计入质量均值。该评分是用户自评，并非医疗检测。

验证：node --test test/*.test.js。桌面浏览器流程可运行 node scripts/verify-profile.cjs、node scripts/verify-vision.cjs、node scripts/verify-plans.cjs 和 node scripts/verify-challenges.cjs。接口按登录会话校验记录所属账号，并检查记录版本，避免不同页面覆盖更新。

“趋势洞察 → AI 健康问诊”支持普通用户与 AI 进行多轮文字交流；游客需要先登录，管理员不能使用个人问诊。对话按账号保存在 data/consult，退出后不再显示；可在问诊页清空当前账号的全部对话。清空不可恢复，请备份需要保留的信息。该功能不会自动读取个人档案、运动、饮食、睡眠或视力记录。普通问题需要在启动服务器前配置兼容 OpenAI Chat Completions 的模型服务：在 PowerShell 中设置 $env:HEALTH_AI_API_KEY、$env:HEALTH_AI_MODEL；如使用其他兼容服务，另设 $env:HEALTH_AI_BASE_URL（须为 HTTPS，或本机 localhost/127.0.0.1）。例如：$env:HEALTH_AI_API_KEY='你的密钥'; $env:HEALTH_AI_MODEL='你的模型名'; npm start。不要把密钥写进网页或提交到仓库。未配置模型时，普通对话会明确提示不可用，不会伪造 AI 回复；急症关键词仍会返回固定的立即就医提醒。使用外部 AI 时，当前提问和最多最近 12 条对话内容会发送给所配置的服务，因此请勿输入身份证号、手机号等不必要的敏感信息。此功能仅提供一般健康信息，不能替代医生诊断、检查或处方；胸痛、呼吸困难、意识改变、大出血等情况应立即联系当地急救服务。API 回归测试见 test/consult.test.js。

顶部导航不再提供页面搜索；天气卡片参考 [weather](https://github.com/wz1229238108/weather) 的天气展示思路，使用 Open-Meteo 实时天气与未来两天的温度预报，并依据当前温度和降雨概率给出简单穿衣提示。默认城市为北京，可手动切换八个城市；“定位”仅在点击并授权后读取浏览器位置。天气请求由本站后端代理并缓存 10 分钟，天气不可用时明确显示失败状态，不填入虚构温度。穿衣提示仅作日常参考，天气数据不写入健康档案。

## AI 近 7 天健康习惯洞察

在“安全健康分析”页，普通用户可主动勾选授权，生成仅针对当前账号近 7 天运动、饮食、睡眠记录的 AI 习惯洞察。后端先按登录会话读取本人记录，再汇总记录天数、运动时长、已记录餐次的热量和蛋白质合计、睡眠时长与可选自评分；把这些汇总指标及从本地知识库检索到的公开资料片段发送给已配置的外部模型，不发送姓名、联系方式、健康备忘、运动项目或食物原文。游客、管理员、未授权请求和没有近期带日期记录的账号均不会调用模型。模型返回的建议与后端生成的数据依据、官方资料链接分开显示，不会自动保存；刷新后需重新授权和生成。

这些指标来自用户自填且可能不完整，未记录不等于没有活动或进食；已记录餐次合计不等于全天总摄入。AI 只给生活习惯参考，不提供疾病诊断、处方或保证性结论。接口与隐私测试见 `test/insight.test.js`。环境变量示例见 `.env.example`，该文件只是模板，Node 服务不会自动加载它。

## 健康知识检索与资料增强回答

“趋势洞察 → 健康知识检索”收录经人工核对的世界卫生组织身体活动、健康饮食和美国 CDC 睡眠页面的简短中文转述。游客可使用无需 AI 的本地关键词检索，并查看每条结果的官方原文链接；登录普通用户主动勾选后，可把本次问题与命中的资料片段发送给已配置的 AI 服务，生成基于这些片段的一般知识回答。个人档案和健康记录不会进入知识问答请求；资料不匹配时不调用模型，急症词触发固定急救提醒。AI 请求按账号限制频率，回答不写入个人档案。资料源在 `health-knowledge.js`，检索与接口测试见 `test/knowledge.test.js`。

资料链接（2026-10-25 核对）：[WHO 身体活动](https://www.who.int/zh/news-room/fact-sheets/detail/physical-activity)、[WHO 健康饮食](https://www.who.int/zh/news-room/fact-sheets/detail/healthy-diet)、[CDC 睡眠](https://www.cdc.gov/sleep/about/index.html)。

这是一个小型、人工维护的本地资料库，使用关键词与同义词匹配，再将命中片段放入模型上下文，属于轻量的检索增强生成；尚无向量数据库、自动网页抓取、Agent 工具调用或多模态能力，不应在参赛材料中夸大。资料可能更新，应以链接中的官方原文为准；此功能不是医疗诊断系统。
